# Submission audit

Compare code and evidence against:

1. Understanding and assumptions.
2. Functional and non-functional requirements.
3. Data model, API contract, and architecture.
4. Concerns/tradeoffs and AI usage disclosure.

Verify that claims match actual routes, request/response schemas, entities/schema, repository structure, tests, and README commands. Use `GIC.md` for the delivery rubric and `docs/02-srs.md`, `05-data-model.md`, `06-api-contracts.md`, and `08-test-strategy.md` for implementation evidence.

Produce discrepancies with file/line evidence and missing evidence. Do not write marketing prose, rewrite history, fabricate AI-use evidence, or silently edit submission documents.
